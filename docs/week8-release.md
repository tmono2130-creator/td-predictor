# Week 8 full-product supervised release

This runbook prepares a release; it does not authorize a push, merge, data proposal, production deployment, settings change or schedule activation. Keep the purple UI and existing V5, PPP, parlay and Market Check calculations.

## Development change

`NFL PM weekly predictions` adds an explicit manual `features` choice, default `core`. Selecting `all` requests the same captured inputs for core TD Rankings, Matchup Intelligence and PPP Game Predictor. Both sidecars must have receipt hashes and the captured bundle must report complete coverage with no unavailable feature. A partial all-feature request fails visibly instead of creating a reduced proposal. Exact offline replay runs before any proposal job.

All-feature generation also builds the website and browser-tests that exact unpublished candidate on localhost before rechecking actual freshness and allowing the protected proposal job. The read-only PR-opening validation job is additionally scoped to `feature/nfl-pm-week8-launch`, explicitly targets 2026 Week 8, and retains its capture, replay, Linux build and real-bundle browser evidence for 90 days. Neither path deploys or changes live JSON. The site defaults to the most recently generated snapshot so fresh Week 8 is not hidden behind the legacy Week 9 export. Cached exact-millisecond clocks avoid false future-timestamp errors without changing freshness limits or kickoff guards.

The protected-file CI audit permits a manifest change only by calling the existing reviewed publication/rollback validator with an explicit PR branch. It preserves every pre-existing snapshot and protected calculation file, rejects untracked or unrelated data, and supports larger legitimate post-publication inventories. Source-only changes must leave the complete live data tree unchanged; the original exact-13 inventory assumption no longer blocks valid data PRs or later source reviews.

Proposal permission is unchanged: `workflow_dispatch` on reviewed `main`, `publish=true`, `NFL_PM_PUBLISHING_ENABLED=true`, and approval of the protected `nfl-pm-production` environment. There is no schedule, direct-main push, merge command or deployment hook. All-feature proposals additionally require the existing `NFL_PM_GAME_PREDICTOR_ENABLED=true` and new `NFL_PM_MATCHUP_INTELLIGENCE_ENABLED=true`; absent/false flags reject before creating a review branch. Their variables are only wired into the protected publisher step; adding source support does not enable them.

Core-only remains backward compatible. The portable publication receipt still validates hashes, exact base manifest, immutable snapshot paths, source cutoff, source identity, code/runtime identity, schedule and kickoff safety. Both sidecars remain optional for old published weeks, and missing data must remain unavailable.

## Injury and external-evidence gate

Roster membership, injury designation and game-day activation are distinct. Unknown injury status is not Active and cannot be fabricated from an empty designation. A week-level injury-file availability flag does not establish coverage of every remaining scheduled team. Review current per-team/player coverage and the actual report statuses; preserve explicit unknowns and disclose them if a supervised release is approved. Use genuine pregame source captures only. Historical revised feeds do not establish original pregame availability, and no historical replay claim is made without genuine archives.

## Evidence retention

The generation workflow requests **90 days** for raw capture and candidate artifacts. The actual expiry must be verified in GitHub after the run. Raw public NFL source bytes, URL, hash, retrieval interval, provider Last-Modified, cutoff, code revision and dependency versions stay in Actions artifacts, outside source Git and production paths. Access requires authenticated repository read access; in this public repository that is broader than project reviewers. This is bounded durable storage, not private reviewer-only or permanent/WORM archival. Do not claim a private archive exists. For a narrowly supervised release, the owner must explicitly accept the access/retention limitation or approve a private archival destination before expiration. Never upload credentials or `.env` files with evidence.

## Unpublished rehearsal and rollback

`python -m unittest test_week8_release -v` exercises captured three-feature generation, exact offline replay, the five-file snapshot plus manifest data contract, served-byte deployment verification and a manifest-only rollback in isolated temporary Git repositories. Synthetic fixtures are explicitly labeled, never production candidates. The test makes no real remote request, review branch, PR or deployment. A separate real Week 8 candidate/browser and isolated staging rehearsal is required before release; retain its exact hashes and results.

Run that real-candidate staging rehearsal with `python release_rehearsal.py --candidate <fresh-candidate-directory> --output work/<new-rehearsal-directory>`. The default `--data` reads the existing production JSON files without changing them. The command creates a new isolated local repository with no remotes, copies the baseline, validates the actual candidate under unchanged current code/runtime/capture guards, rechecks the current public NFL schedule, stages a five-file snapshot plus manifest, verifies every simulated served byte/hash, and restores only the original manifest while retaining all snapshots. It records artifact/manifest hashes and isolated fixture commit IDs in `rehearsal-result.json`. These are rehearsal fixture commits, not production commit IDs, and the simulated HTTP verification is not a claim of a Vercel deployment. The only network operation is read-only schedule retrieval. No clocks or provenance guards are replaced by the command; only explicitly synthetic unit tests replace their fixture clock and schedule.

For a live incident, first stop proposals and coordinate pending deployments. With separate owner approval, select the recorded known-good Vercel production deployment for Instant Rollback, verify the restored alias/content, then restore only the previous manifest through `nfl-pm/rollback/<incident>` and a reviewed manifest-only PR. The previous manifest must match an actual ancestor byte-for-byte. Keep every immutable old/new snapshot, including the failed release, for audit. Never revert a whole data commit if that deletes snapshots; never reset/force-push main. Vercel rollback can disable automatic domain assignment; restore promotion only after separate review. Verify the exact rollback commit/deployment/alias and JSON before closing the incident.
